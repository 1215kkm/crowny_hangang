🧪 강디1 — 플로우 진단

v2의 4탭(홈·매칭·채팅·프로필) 구조는 단순성 기준 통과. 문제는 "손흔들기→비공개방 입장" 분기가 사용자 머릿속에 안 그려진다는 것.

현재 비공개방 입장 플로우 (3단계가 권고 — 지금 5단계)

Mermaid (렌더 안 되면 그냥 읽기용):

flowchart LR
  A[채팅 탭] --> B[비공개방 자물쇠 탭]
  B --> C[아코디언 펼침
방장 카드+매너태그]
  C --> D[손흔들기 버튼]
  D --> E[방장 수락 대기]
  E --> F[방 입장]

  style D fill:#ffe9f0,stroke:#D53A6B
  style E fill:#fff3d6,stroke:#f59e0b

문제 3가지:

  1. 대기 상태(E)가 화면 어디에 사는지 불명 — 푸시 외엔 회수 경로 없음. "내 손흔들기" 목록이 필요.
  2. 공개방은 1탭, 비공개방은 2탭 — 같은 카드 컴포넌트에 다른 액션. 멘탈모델 깨짐.
  3. "손흔들기"가 매칭 탭에도 있음 — 어디서 한 손흔들기인지 사용자가 못 추적.

제안: "내 활동" 모드만 추가. 채팅 탭의 필터 (전체/참여중/1:1) 옆에 "보낸 손흔들기" 한 칸 더. 새 페이지 X, 필터 1개 추가.

한 화면 = 한 목표 원칙: 매칭 페이지는 "누구를 발견", 채팅 페이지는 "누구와 진행 중". 손흔들기는 "진행 중"이지 "발견"이 아님.

🎨 강디2 — 디자인 시스템 정합성

코드를 훑었는데 임의 HEX 두 곳 발견. v2.1까지 오면서 토큰이 슬며시 새는 중.

발견 위치임의 값제안 토큰
flutter — 채팅 참여중 아이콘파란색 (커밋 42d8d5f)--color-info로 토큰화 (지금 토큰 없음 → 디자인 시스템 문서에 먼저 추가)

제안 — Crowny Class 디자인 시스템 v2 갱신:

  • 색 토큰 3개 추가: --color-info (참여중/진행중), --color-warn (마감임박), --color-muted

⚙️ 강개발 — 서버↔앱 연결 갭

스키마는 Prisma 14모델로 잘 잡혀 있는데, Flutter 앱은 mock_data.dart만 본다. 즉 v2.1까지의 모든 화면은 서버 0줄도 호출 안 함.

현재 아키텍처:

[Flutter app] ─ mock_data.dart ─ (끝)

[server]
  src/app.js ─ Express
  prisma/   ─ User/MoimRoom/RoomMission/ChatMessage/TrustVote/Wave...
  Socket.io ─ 초기화만, 핸들러 없음
  Redis     ─ 의존성만, 연결 안 됨

[admin]    ─ 별개 SPA (slot in tree)

최소 연결 셋 (MVP 1주차):

POST  /auth/firebase         // Firebase ID 토큰 → 서버 JWT
GET   /matching/nearby       // 위도/경도 + 반경 → User 리스트
POST  /rooms                 // 모임방 생성
GET   /rooms?district=뚝섬   // 모임방 목록
POST  /rooms/:id/join        // 공개방 입장
POST  /waves                 // 비공개방 손흔들기
WS    /chat                  // Socket.io 그룹/DM 채팅
WS    /mission/tick          // 미션 타이머 동기화

리스크: 위치 푸시(/matching/nearby)를 polling으로 갈 거냐 GPS subscribe로 갈 거냐 — 배터리 vs 신선도 트레이드오프. 1주차는 30초 polling 권장 (베타 10명엔 충분).

Redis는 1주차에 빼도 됨 — Postgres + Socket.io adapter만으로 10명 트래픽 처리. "세 번째 비슷한 케이스가 보일 때" 추상화 룰 따라가자.

🛡️ 강감시 — 리스크 + 우회안

오프라인 매칭은 본질적으로 안전 리스크가 큰 도메인. "안 됩니다"가 아니라 비즈니스 의도를 유지하는 우회안까지.

리스크심각도우회안
위치 정확도 노출 (스토킹)🔴 치명거리 표시는 3구간만: 100m 미만/100m~1km/1km+. 정확한 좌표는 서버도 저장 X (반경 그리드 cell ID만)
비공개방 손흔들기 스팸🟡 중간1인당 시간당 5회 rate limit + 거부 3회 시 24h 차단 (DB Wave 모델에 cooldown_until 추가)
익명 게시판 → 명예훼손🟡 중간익명은 표시만 익명. 서버는 작성자 ID 보존 (수사 협조 가능 명시) + 신고 3회 시 자동 가림
미성년자 가입🔴 치명PASS 본인인증 필수 (만 17세+). Phase 1에 본인인증 없으면 출시 불가
DM에서 개인정보 강요🟡 중간전화번호·인스타·카톡 ID 패턴 감지 → 회색 처리 + "정말 보내시겠습니까" 한 단계
외국인 사기 (피싱·로맨스 스캠)🟢 낮음(현재) → 🟡(외국인 모드 후)Stage 3 연락처 공개 전까지 결제·송금 키워드 차단

법규 체크: legal/privacy.html·terms.html은 있는데 위치·생체(셀카 미션) 항목이 약함. 개인정보처리방침에 "위치 정보 그리드 cell 저장, 정확좌표 저장 X" 명시 필요.

Phase 1 출시 차단 조건 한 줄: PASS 본인인증 + 긴급신고 + 거리 3구간 표시. 이 셋 없이 출시는 강사장 경유 강사님께 직보.

💡 아뱅 — 정석 깨기

강팀이 너무 잘 정리해서 끼어들어야 함. 지금 안이 정석으로 굳어가는 게 보임. 토큰은 안 깬다 — 깨는 건 심리 레버.

레버 1: 마감 임박 = 손실회피

강홍보 카피 B 좋은데 한 단 더. "옆자리 그 사람, 같이 라면 먹자고 해볼래요?" → "옆자리 그 사람, 10분 뒤엔 사라져요". 모임방 카드에 "방장이 26분 뒤 떠남" 표시 — 이미 RoomMission timerSec 있으니 방장 체류 시간만 한 줄 더.

레버 2: 미션은 "핑계"라는 프레임을 광고로

강디1이 잘 짠 미션 시스템의 진짜 가치는 "어색함 해결"이 아니라 "미션이 시켜서요"라는 핑계 제공. 이걸 마케팅이 안 쓰고 있음.

"먼저 말 거는 게 어려우세요?
 미션이 대신 말 걸어드려요."
─ Before/After ─
Before: 침묵 → 도망
After : 미션 알림 → "아 이거 시켜서…" → 웃음 → 대화

레버 3: 한강 11지구 ≠ 11등급

지구별 접속자 수 표시를 "127명" 식 숫자가 아니라 "오늘 뚝섬이 제일 뜨거워요" 식 비교로. 같은 데이터, 다른 프레임 = 경쟁사가 못 따라옴.

한 줄: 화면 하나 추가 X. 카피·타이밍·표시 프레임 3개만 비틀자. 토큰 안 건드림.

🔍 강체크 — 회귀·엣지 케이스

v2.1까지 16개 수정요청 처리하면서 회귀 가능성 높은 곳들. 사용자 관점에서 가장 빨리 깨지는 지점부터.

#케이스예상 결과실제 (테스트 필요)
1글자크기 +3 상태에서 모집글 작성 입력독바 아래로 본문 안 가려야 함❓
2비공개방 손흔들기 → 방장 거절"거절됨" 상태 어딘가 보임❌ (강디1 지적대로 회수 경로 없음)
3모집글 미션 60분 → 백그라운드 30분 후 복귀타이머 30분 남아야 함❓ (서버 동기화 없음 → 부정확)
4채팅 필터 "1:1" 상태에서 새 모임방 알림필터 유지, 알림은 배지로만❓
5한강 지도 가로 스크롤 + 글자크기 +3레이아웃 안 깨져야 함❓
6익명 게시글 작성 → 작성자 본인이 보기본인은 "내가 쓴 글" 표시❓
7로그아웃 → 로그인 페이지 (독바 없음)독바·햄버거 모두 X✅ (의도된 것 확인됨)
8"한강근처" 배지 — GPS 거부 사용자배지만 사라지고 기능은 작동❓

디자인 시스템 토큰 회귀: 강디2가 지적한 임의 HEX 2건은 회귀 테스트 자동화로 잡자. 빌드 단계에 grep -E "#[0-9a-f]{3,6}"로 토큰 외 색 감지.
